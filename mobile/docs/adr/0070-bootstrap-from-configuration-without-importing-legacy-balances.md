# Bootstrap from configuration without importing legacy balances

Before a Profile first exposes the Companion Snapshot Capability, the Engine will atomically publish a no-network Configuration Bootstrap containing current Source configuration and durable identities, Manual Entries, bounded local History, Profile settings, and the closed Asset Catalog. Every external Source keeps its real enabled flag but starts with `data_state: never_refreshed`, no attempt, and no Balance Contributions, so Snapshot Coverage explicitly reports missing initial coverage and the Client offers a user-initiated global Refresh. The bootstrap imports neither aggregate historical snapshots nor legacy blockchain and in-memory exchange caches: those stores have asymmetric durability and cannot prove complete per-Source origin and capture semantics. Manual amounts remain visible, with null valuation whenever coherent local-only pricing is unavailable; durable History is not externally synchronized. This creates a truthful immediately usable encrypted offline document without inventing zero balances or violating the policy that expensive Refresh requires explicit user action. Typed `503 snapshot_unavailable` remains only for incomplete or failed bootstrap/publication, and restart recovery never resets existing durable Companion source state.
