# Reference Events from History summaries

`HistoryGroup.summary` will be a closed structural union owned by the Engine. Every variant carries a `kind`, one `primary_event_id`, and only the additional Event-ID role arrays needed to explain proven group topology; asset identifiers, amounts, valuations, timestamps, Source IDs, protocol IDs, and display prose remain solely on the referenced History Events. Every reference must resolve exactly once inside the same complete Group, mutually exclusive roles cannot overlap, and role arrays follow canonical Event order. A specialized summary is emitted only when the complete included topology can be assigned without guessing; mixed, incomplete, ambiguous, or future patterns use a generic primary-Event form. Native Clients dereference the same Events for rendering and never recompute classification from type/subtype combinations. This keeps the Engine authoritative over topology while preventing duplicated financial facts, inconsistent revisions, and unnecessary Snapshot bytes.
