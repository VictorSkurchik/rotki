# Embed a minimal asset catalog in each snapshot

Every Portfolio Snapshot will embed one deduplicated Asset Catalog keyed by all canonical Engine asset identifiers referenced by its Balance Contributions, bounded History, and Valuation Currency. Each entry contains nullable name and symbol plus a required tolerant asset type; the Engine synthesizes an `unknown` entry when existing metadata lookup omits an identifier, and Clients always retain the financial object and fall back to displaying its exact identifier. Metadata is not repeated per contribution and is not fetched into a separate mobile cache, preserving the Snapshot as the one atomic authenticated-encrypted offline document. Icons and URLs, oracle identifiers, collections, spam heuristics, prices, internal protocol labels, and global-database fields remain outside the version-1 catalog. Metadata changes affect Snapshot Revision, while map ordering does not. This gives Android and iOS complete offline presentation data without allowing incomplete or evolving global metadata to erase portfolio facts.
