# Store device registrations in a durable control store

The Engine will add a migrated host-local `control.db` beside its disposable session database to persist opaque 256-bit Device Session IDs, Profile bindings, device labels, platform, Pairing and last-seen timestamps, and public Device Keys only while their Device Sessions remain authorized. Revocation atomically removes the public key and algorithm but retains the non-authorizing identity and timestamps indefinitely for the version-1 owner audit; an audit record can never become authorized again, and unknown and revoked IDs expose the same protocol outcome. This Control Store is available while the Profile is locked and contains no Profile name, password, private key, bearer token, portfolio state, trusted Engine origin, or other secret; Pairings, challenges, and Access Session membership remain disposable and separate.

The Control Store is an authorization database for one Engine Host, not Profile data. Automatic Profile backup, premium synchronization, and development-instance seeding therefore exclude it. A restored or concurrently cloned Profile keeps its Profile ID and remains in the same authorization lineage, so an existing same-host registration still matches it; another host has its own Control Store. Restoring an older Control Store can resurrect authority revoked after that snapshot, so copying it is unsupported except as an explicit, consistent whole-host recovery. If the store is corrupt, malformed, or from an unsupported future schema, the Engine keeps ordinary Full Client operation available but disables the Companion `device_sessions` Capability; it neither silently recreates authority nor reports the failure as `not_authorized`.
