# Extend the existing engine protocol

The mobile Clients will consume the existing versioned HTTP and WebSocket Engine Protocol used by the Full Client. One canonical Engine origin serves all new HTTP resources beneath `/api/1/companion/*` and the existing WebSocket at `/ws`; a separate WebSocket host or port is not part of the protocol. `GET /api/1/companion/protocol` is the unauthenticated Capability bootstrap, and the remainder of the subtree uses a dedicated deny-by-default authorization matrix whose credentials never grant access to general `/api/1` routes. Pairing, Device Session management, and any demonstrably necessary Companion aggregates will be added compatibly without breaking the Full Client; a mobile-specific BFF and a wholesale API v2 redesign are outside Companion Scope.
