# Order History Groups by their latest event

`HistoryGroup.occurred_at_ms` will be the maximum millisecond timestamp across every included event in the complete curated display group, computed after the underlying entitlement window, exact movement or bridge joining, and projection inclusion rules, but before Snapshot bounds or request filters. This treats a multi-time activity as occurring at its latest, typically completion, leg and prevents recently completed activity from being evicted merely because it joins an older constituent. Edits, re-decode, joins, and splits recompute the value and may move a lineage-stable Group ID; timestamps never establish identity, and History Generation fencing restarts any pagination whose order changed. This replaces the current ambiguous aggregate-header timestamp with one deterministic rule already aligned with the Engine's group-position use of `MAX(timestamp)`.
