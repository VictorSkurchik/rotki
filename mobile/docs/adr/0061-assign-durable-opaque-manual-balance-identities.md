# Assign durable opaque identities to manual entries

Every Manual Entry will receive a Profile-scoped Manual Balance ID made from 16 cryptographically random bytes and encoded as 22 characters of canonical unpadded Base64URL. The ID is persisted with encrypted Profile data, survives changes to every editable entry field and backup/restore, and is never derived from the entry's legacy integer row ID, label, asset, amount, location, category, tags, or any deterministic hash. Deleting an entry retains an opaque ID-only tombstone so that the identifier is permanently retired; re-adding equivalent data receives a new identity. A transactional migration assigns and collision-checks IDs for existing entries before the Companion Snapshot Capability becomes available. The current integer identifier remains available to existing Full Client CRUD internals but is excluded from the Companion wire contract because SQLite can reuse it after deletion. This gives encrypted Snapshots and native navigation stable equality without confusing a deleted entry with a later one or leaking mutable financial metadata into identity.
