# Model manual entries separately from portfolio sources

The Portfolio Snapshot will preserve every manually tracked fungible asset or liability as a read-only Manual Entry rather than model it as a Portfolio Source or hide it inside an unattributed aggregate. Each Balance Contribution has exactly one discriminated origin: a `source_id` for an independently refreshable external Source or a `manual_balance_id` for a Manual Entry. Manual Entries participate in exact Portfolio and Overview aggregation and encrypted offline presentation and carry their Full Client-selected Allocation Location, but they have no Source ID, enabled state, Source Health, Snapshot Coverage reason, execution generation, or Refresh action; creation, editing, and deletion remain Full Client workflows. The Engine must project manual contributions before its existing aggregate paths lose their provenance. Each Manual Balance ID is a Profile-scoped 16-byte cryptographically random value encoded as canonical unpadded Base64URL, preserved across edits and backup/restore, and permanently retired after deletion so that a re-added entry receives a new identity. A transactional migration assigns IDs to existing entries before Companion Snapshot access is enabled. The existing mutable API's integer identifier remains an internal CRUD key because it may be reused after deletion and therefore cannot satisfy the wire identity contract.
