# Standardize the Android presentation stack

Android will use Koin as its platform-local dependency-injection container, Jetpack Compose for rendering, MVI with unidirectional data flow for screen presentation, and typed Navigation Compose destinations for navigation. Koin is restricted to Android composition roots and feature DI modules; shared KMP, domain code, and Swift-facing APIs remain framework-free and receive dependencies through constructors. Each screen exposes immutable `UiState`, accepts typed `UiAction`, and emits only bounded one-shot `UiEffect` values when an outcome cannot be represented as durable state; Compose routes collect state and dispatch actions while stateless screens render values and callbacks. Shared state machines remain authoritative for domain transitions instead of being duplicated in Android reducers. UI remains custom and based on Material 3, but the complete Rotki design system is deliberately deferred to a separate final Claude Design step after functional destinations stabilize; until then the application uses only minimal semantic tokens and feature-local components. Claude Design output is a proposal until explicit human approval and repository versioning make it the implementation contract. That final system will follow Atomic Design from tokens and atoms through molecules, organisms, and templates while feature screens remain feature-owned. `NavController` never enters a ViewModel, domain object, or shared module. This stack favors predictable state, testable boundaries, native accessibility, and a coherent custom visual language over ad-hoc service location, imperative screen mutation, and stringly typed navigation.
