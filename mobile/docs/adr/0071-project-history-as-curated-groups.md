# Project History as curated groups

Companion History version 1 will use a bounded group-centric read model instead of mirroring the general `/history/events` response. Every complete display-oriented History Group contains a typed summary and ordered typed History Events with only explicitly allowlisted details; arbitrary `extra_data`, accounting metadata, raw database identifiers, mutable Engine group keys, and transaction-derived values used as identities remain backend-only. Public `group_id` and `event_id` values are opaque Profile-scoped Companion identities used only for equality, ordering tie-breaks, pagination, and deduplication. The Snapshot orders groups by `(occurred_at_ms DESC, group_id ASC)` and nested events by `(sequence ASC, event_id ASC)`, applies measured group-count and encoded-byte bounds only at whole-group boundaries, and replaces the complete History section atomically. Older groups and details may be paged online into foreground memory but never expand the encrypted offline Snapshot. Durable ID reconciliation is governed by ADR-0072, the offline detail boundary by ADR-0073, and projection inclusion by ADR-0077.
