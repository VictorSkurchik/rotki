# Negotiate engine protocol capabilities

Before Pairing and normal online use, a Client will call the public `/api/1/companion/protocol` resource, select the greatest shared positive-integer Protocol version, and advertise it through `Rotki-Companion-Protocol` on every later HTTP request and mobile WebSocket Upgrade. The Engine advertises a map of stable Capability names to their greatest backward-compatible integer schema versions; the initial registry covers Device Sessions, Portfolio Snapshot, History pagination, Refresh Operations, and WebSocket notifications. A Client enables each function only when its Capability meets the required minimum. Additive unknown response fields and capabilities remain compatible, missing required fields fail their typed contract, and an incompatible Engine disables only affected online functions with an explanation while leaving the encrypted offline Portfolio Snapshot available; matching application build versions or SemVer is not required.
