# Add mobile authorization without migrating existing clients

Vue will retain its HttpOnly cookie flow and MCP will retain its purpose-separated credential flow, while Device Key authentication and short-lived Access Sessions form separate Companion authorization realms. Single-use Pairing and in-memory Access credentials are independent opaque 256-bit values transported only through the standard `Authorization: Bearer` header on routes whose deny-by-default matrix selects the expected credential store; they are never interchangeable with each other, browser cookies, MCP credentials, or general `/api/1` authorization. The existing `/ws` handshake accepts exactly one realm: the browser cookie retains its current behavior, while a mobile bearer is validated before accept and creates only a Companion-filtered subscriber; a handshake carrying both is rejected. A Vue login for the same Profile does not revoke mobile Device Sessions, and mobile revocation invalidates its Access Sessions and WebSockets without changing browser or MCP credentials; a wholesale authentication migration is outside the Companion scope.
