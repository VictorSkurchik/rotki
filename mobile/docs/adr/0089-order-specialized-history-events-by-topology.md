# Order specialized History Events by topology

Before assigning dense public ordinals, the Engine will order a specialized History Group by proven Summary topology: `swap` uses spend, receive, fee, then auxiliary Events; `movement` and `bridge` use out, in, fee, then auxiliary Events. An `activity` Group preserves the Engine-authored presentation order for every included Event. Within each role or auxiliary bucket, the Engine preserves its deterministic authored order and uses the opaque Event ID only as a final tie-break for otherwise equal internal keys. Auxiliary means every included Event not referenced by a specialized Summary role, including gas, informational, adjustment, or future unknown-code Events; the projector never reclassifies them from mutable type/subtype labels. Role arrays follow this resulting Event order, and dense `sequence` is assigned afterward. A public reorder advances History Generation but does not alter proven identity. This gives native specialized cards one predictable directional order without attempting a global semantic sort of mixed or unknown activities.
