# Match History filters within one Event

Curated History filtering will evaluate date and group-kind predicates on the complete History Group, while one and the same included History Event must satisfy every active Event-scoped predicate: asset ID, event type, event subtype, and Source ID. Values within one dimension use OR, dimensions use AND, and an absent dimension is true; a Source predicate matches when that Event's proven `source_ids` intersect the requested set. The derived group-level Source union is never used to correlate one Event's asset with another Event's Source or type. Once a group matches, the Engine returns the unchanged complete group, including non-matching legs, and does not recompute its occurrence time, summary, Source union, or Asset Catalog closure. This deliberately prevents false cross-leg matches such as treating `spend ETH / receive USDC` as `asset=ETH + subtype=receive`, and it rejects the general History API's partial-row response behavior in favor of the group-complete Curated History contract.
