# Assign durable opaque identities to portfolio sources

Each Portfolio Source will receive a Profile-scoped Source ID made from 16 cryptographically random bytes and encoded as canonical unpadded Base64URL. A Source is the smallest independently refreshable configured external origin: one `(blockchain, address)` pair or one named exchange connection, rather than a whole provider, chain, asset, balance, or Manual Entry. Consequently the same address on two chains and two connections to one exchange provider have distinct identities. The ID is persisted with encrypted Profile data, survives rename, credential rotation, backup, and restore, and is never derived from an address, provider name, credentials, row number, or deterministic hash. Human-readable metadata remains separate: the authorized encrypted Snapshot carries full canonical chain addresses plus optional labels, or exchange provider plus connection label, but never credentials, credential fingerprints, or provider account IDs. Every Source kind preserves a common identity, Allocation Location, enabled state, and health envelope, so an older Client retains an unknown kind as an Unsupported Source in totals and offline data while disabling only targeted Refresh. Deleting a Source destroys its active configuration and credentials but permanently retires its opaque ID; re-adding the same natural Source receives a new identity. A transactional Profile migration assigns IDs to existing Sources before Companion access is enabled. This avoids leaking natural identifiers into URLs and events, prevents a deleted Source from being confused with a later configuration, and gives Snapshots, Source Health, Refresh Operations, and native navigation one stable equality key.
