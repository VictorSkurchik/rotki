# Attribute History at the Event boundary

Each Companion History Event will carry zero or more sorted opaque Source IDs backed by a durable Profile-owned provenance relation; a History Group's Source IDs are exactly the sorted union of its included Events rather than an independently inferred label. The Engine records a relation only when it can prove the configured origin, such as a canonical `(blockchain, tracked address)` Source or one exact named exchange connection. It never guesses from `location`, `location_label`, provider name, transaction contents, or display grouping; imports, manual or synthetic events, ambiguous exchange records, and other unprovable cases remain unattributed. Joining groups unions their Event provenance without rewriting it, and the Group's display location neither proves nor limits that union. Deleting a Source retires its ID but preserves existing History relations, and the bounded History section exposes referenced retired IDs only as Removed Sources; re-adding the same natural origin receives a new ID and cannot capture old relations. Source lookup and Refresh still reject a retired ID, while an authenticated History filter may accept a tombstone issued by the same Profile without revealing former Source metadata. Provenance changes commit with the History mutation, generation, and publication-dirty record, survive exact lineage-preserving re-decode and Profile backup/restore, and are backfilled conservatively before the Capability is enabled. This supports honest per-leg origin display and Source filtering while accepting an explicit unknown result instead of false attribution.
