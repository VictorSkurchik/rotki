# Store only typed History details offline

The encrypted offline Snapshot will retain useful transaction inspection through closed typed History Detail variants: validated canonical transaction references and involved addresses for declared on-chain and movement records, canonical protocol IDs, and typed validator, block, deposit, and withdrawal facts. These values remain data rather than public identity and are redacted from every log or secondary store. Version 1 will not persist account or location labels, user or generated notes, arbitrary counterparties, exchange internal references, merchant or IBAN prose, URLs, accounting state, or unknown `extra_data`; native Clients derive localized summaries from typed fields, and an unrecognized detail is omitted without dropping its common event. This accepts the incremental correlation sensitivity of transaction references and addresses because offline transaction details are a core Companion use case, while excluding uncontrolled free text and internal payloads keeps the encrypted read model bounded and auditable. A disconnected Client may retain its previous authenticated Snapshot until it Fetches a newer Revision, so remote History edits or deletion do not claim instantaneous offline erasure.
