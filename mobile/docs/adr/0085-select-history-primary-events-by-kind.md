# Select History primary Events by kind

The Engine will derive `primary_event_id` after Curated History inclusion through one deterministic kind-specific rule over canonical `(sequence, event_id)` order. A `swap` selects its first spend Event; a `movement` selects its first non-fee typed Asset Movement Event; a `bridge` selects its first out Event, or its first in Event when one-sided inbound; and `activity` selects its first non-fee Event, falling back to its first Event for a fee-only Group. A fee is never primary while an eligible non-fee Event exists, and nullable or changing monetary value never participates. The selected ID must reference exactly one included Event and, for a specialized Summary, its declared main role. Reordering or role changes may change the primary reference and therefore History Generation, but never establish, preserve, or transfer Group or Event identity. This replaces accidental SQL/header selection with a stable contract while retaining the existing desktop preference for a typed Asset Movement anchor.
