# Derive profile-scoped revisions from canonical content

Snapshot schema version 1 will derive its opaque Revision as unpadded Base64URL of SHA-256 over a domain-separated, length-prefixed preimage containing the schema version, the stable internal Profile ID bytes, and the RFC 8785 canonical JSON bytes of the complete revisionless Snapshot document. Before canonicalization, every array is sorted by a schema-owned domain key and every exact decimal is normalized; ordinary response bytes, map or query order, request time, the HTTP envelope, presentation derivations, and `revision` itself are excluded. The Engine persists an encrypted Profile-scoped publication record containing a semantic-candidate fingerprint, one stable `captured_at`, and the resulting Revision: unchanged content reuses that record across Fetches, normal restarts, and backup/restore, while changed content is atomically published before notification. Clients validate the 43-character encoding and compare only for equality; the digest has no ordering and provides neither authorization nor authenticity. This makes semantically identical Snapshots stable, prevents irrelevant serialization order from causing encrypted writes, namespaces equal portfolios across Profiles, and leaves algorithm evolution explicit through the schema-versioned preimage.
