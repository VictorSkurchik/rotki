# Serve only atomically published snapshots

The Companion `GET /snapshot` endpoint will serve only the last immutable Published Snapshot stored with the encrypted Profile and will never assemble a response from mutable blockchain, exchange, manual, price, or History caches. Refresh Operations perform remote work without a publication lock and keep detached per-Source results in operation-local staging. After all Sources covered by a global operation settle, or the one Source covered by a targeted operation settles, the Engine takes a short Profile-scoped publication mutex and one user-database transaction, reloads the latest durable Companion source state, applies generation-valid successes, retains failed Sources' last-known contributions with updated health, rebuilds the entire document, and atomically commits it. Independent targeted commits serialize and merge from latest state to avoid lost updates. Fetch returns the prior revision while work is active; no global Refresh emits intermediate per-Source revisions. Only after commit may an operation become terminal or events be emitted. Publication failure leaves the prior document authoritative. A no-network Configuration Bootstrap normally supplies the first document, while failure or absence of that publication yields typed `503 snapshot_unavailable` rather than an invented empty portfolio. This isolates Companion consistency from existing per-chain swaps and per-exchange caches without holding a global lock across network I/O.
