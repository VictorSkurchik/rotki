# Use Ktor for the shared engine protocol client

The shared core will implement HTTP and WebSocket access with Ktor Client and Kotlin serialization, using the OkHttp engine on Android and the Darwin system engine on iOS. It derives `wss` `/ws` from the same canonical HTTPS Engine origin used for `/api/1`, without accepting a second WebSocket address, and supplies the in-memory Access Session as a Bearer header during the native WebSocket Upgrade. One shared request policy permits two retries for safe GETs and one for idempotent writes only on pre-response transport failure or `408/429/502/503/504`, with 250 ms exponential full jitter capped at two seconds and immediate foreground cancellation; challenge/proof is never retransmitted. Access Session renewal, authenticated reconnection, typed serialization, and event handling remain in that pipeline while TLS trust and low-level transport stay with the platform engines; dependency versions are selected together at scaffold time rather than frozen by this decision.
