# Page History with generation-fenced keysets

Older Companion History will use whole-group keyset pagination in the fixed `(occurred_at_ms DESC, group_id ASC)` order, anchored by the current Published Snapshot and fenced by its internal History Generation. A first request requires that Snapshot Revision; every opaque short-lived cursor binds its canonical filters, page limit, exclusive last key, Device Session, generation, and History Entitlement. Any mutation or effective-entitlement change that can affect the curated History projection increments the generation, so a continuation then fails with typed `409 history_changed / fetch_snapshot`; the Client discards only foreground online pages, Fetches the new Snapshot, and restarts instead of silently mixing versions. Responses include complete groups, a page-local Asset Catalog, and an explicit exhausted-versus-entitlement terminal reason, but no offsets, page numbers, or unstable total counts. This deliberately accepts an occasional restart during concurrent edit, re-decode, or subscription change to avoid the duplicate and gap behavior of the existing offset API without retaining a long SQLite transaction or materializing a sensitive server-side result snapshot across requests.
