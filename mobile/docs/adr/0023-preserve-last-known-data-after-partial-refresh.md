# Preserve last-known data after partial refresh

A partially successful global Refresh will produce a Degraded Snapshot: newly refreshed Portfolio Sources advance, failed Sources retain their last-known values, and each Source carries orthogonal `data_state`, capture time, last-attempt outcome, and typed-error facts. All Source work remains operation-local until every selected Source settles; one Profile-scoped transaction then merges staged successes and retained failures into durable Companion source state and publishes the complete immutable document, while Fetch continues serving the prior revision. Snapshot Coverage and its Source-specific reasons are derived exhaustively in shared code from that complete collection rather than duplicated in top-level wire fields or reinterpreted by each native Client. Active Refresh state is overlaid from the disposable operation registry rather than persisted as Source Health. A Full Client-disabled Source likewise remains visible, keeps its last-known value in aggregate totals, and makes the Snapshot degraded with the distinct `disabled` reason; a never-refreshed disabled Source contributes no invented value but still makes coverage incomplete. The atomic Degraded Snapshot is committed before the Refresh Operation transitions to terminal `failed / source_refresh_failed`, and that operation points to the resulting Snapshot Revision; `failed` therefore means the requested target was not fully refreshed, not that successful Source effects were rolled back. Conversely, a global operation may succeed while its Snapshot remains degraded because disabled Sources were deliberately excluded. The aggregate operation error contains no upstream or Source details, so Clients Fetch Source Health for presentation. The Client presents an overall degraded status and never interprets an unavailable Source as a zero balance; an atomic Snapshot write therefore represents a coherent mixed-freshness view rather than all-or-nothing freshness.
