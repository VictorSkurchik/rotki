# Pair mobile devices with a one-time QR code

A new mobile Client will be approved from an already authorized Client using a two-minute, single-use QR payload constructed by the Engine as strict versioned JSON. It contains only its format marker, canonical HTTPS Engine origin, opaque Pairing ID, 256-bit Pairing credential, and Engine expiry; it exposes no Profile or portfolio metadata and carries no second WebSocket URL or certificate pin. Registration sends the credential only as a Bearer header and submits the Device label, platform, fixed P-256 algorithm, and public key in a redacted body. Single-use means one logical Device Session registration: the registration carries a random `Idempotency-Key`, and an exact transport replay may recover the same result but can never register a second key or change the payload. Successful Pairing registers the Client's Device Key and creates an independently revocable Device Session; the private key remains in the mobile operating system's secure credential storage, and the Profile encryption password is not transferred to or retained by the paired mobile Client.
