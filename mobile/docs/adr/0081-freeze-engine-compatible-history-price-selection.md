# Freeze Engine-compatible History price selection

The History valuation projection will use a versioned cache-only selector compatible with the Engine's native historical-price lookup. It floors each Event timestamp from milliseconds to a UTC epoch second; identical asset and valuation currency use unit price `1`, while every other Event requires a direct local `(asset_id, valuation_currency)` pair. Eligible records lie in an inclusive plus-or-minus 3,600-second window, widened to 86,400 seconds only for fiat-to-fiat pairs. Minimum absolute timestamp distance wins; only an equal-distance tie prefers MANUAL, then the captured effective historical-oracle order, then a stable canonical source identifier. A stored zero is a genuine price, while no eligible row yields null. The selector performs no remote lookup, current-price fallback, or general FX triangulation. Its policy version, source eligibility and order, and time windows are frozen for each controlled projection run. Relevant historical-price add/edit/delete or cache replacement, main-currency changes, oracle-order changes, Event changes, and future selector-version upgrades stage deterministic revaluation and advance History Generation only when public values actually change. This preserves current Engine behavior while closing its otherwise under-specified database tie ordering for canonical cross-page output.
