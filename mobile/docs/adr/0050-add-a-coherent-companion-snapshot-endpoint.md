# Add a coherent companion snapshot endpoint

The Engine Protocol will add an aggregate endpoint that serves one immutable atomically Published Snapshot rather than joining mutable live caches during Fetch. External Refresh work stages detached Source results; one short Profile-scoped transaction merges valid results into durable Companion source state, retains failed last-known data, and publishes the full revisioned document only after the covering global or targeted operation settles. Fetch keeps returning the previous valid revision during that work, and operation terminal state plus notifications occur only after publication commit. The document contains Overview, fungible Portfolio with contribution-level origin attribution, read-only Manual Entries, Sources with Source Health, a bounded recent History window, and one minimal Asset Catalog covering every referenced identifier. Every contribution identifies exactly one Portfolio Source or Manual Entry before exact aggregation, and version 1 emits exactly one row per `(origin, category, asset_id)` after summing internal protocol or provider buckets; Manual Entries remain outside Source Health, Snapshot Coverage, and Refresh targeting. Each origin also owns a canonical Allocation Location, so per-location assets, liabilities, and known net values form an exact partition without the legacy rule that assigns every liability to blockchain. The Snapshot captures one explicit Profile main currency and expresses every valuation and aggregate in it, so a Full Client currency change produces new canonical content rather than locally relabelling old values. Its opaque Profile-scoped Revision is an unpadded-Base64URL SHA-256 digest of the schema-normalized RFC 8785 document and a domain-separated stable Profile ID; an encrypted publication record keeps `captured_at` and revision stable for unchanged semantic content across Fetches, restarts, and backup/restore. This document is the atomic input to encrypted offline persistence, while older History continues through existing pagination; the endpoint is an additive Engine read model rather than a separate mobile BFF.
