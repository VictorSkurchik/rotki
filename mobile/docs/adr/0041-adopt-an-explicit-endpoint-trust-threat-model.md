# Adopt an explicit endpoint-trust threat model

The Companion security design will defend against network interception, replayed Pairing codes or authorization challenges, stolen Access Sessions, resource exhaustion, and access to a stolen locked phone. Pairing codes are single-use and live for two minutes; each Device Session has one replaceable single-use authorization challenge that lives for 60 seconds; Access Sessions live for 15 minutes and are renewed by a fresh proof, never a refresh token. Challenge/proof work is bounded by per-device, trusted-source, and process token buckets before signature verification or mutation. A Device Key proof signs a normative, versioned, domain-separated binary transcript containing the canonical Engine origin, Device Session ID, Challenge ID, random nonce, and expiry, preventing a proof from being transplanted to another Engine, device registration, challenge, protocol, or lifetime. Cross-language golden vectors, concurrency, rate limiting, revocation, and device authentication are required. A compromised Engine Host, malicious operating system, or an already unlocked rooted or jailbroken phone is outside the protection claim and must be stated as such.
