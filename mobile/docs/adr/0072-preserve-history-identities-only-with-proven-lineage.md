# Preserve History identities only with proven lineage

Every Companion History Group ID and History Event ID will be a random 16-byte value encoded as 22-character unpadded Base64URL and persisted with never-reused tombstones in the encrypted Profile DB independently of mutable or cascade-deleted Engine history rows. IDs survive ordinary edits, backup/restore, and re-decode only when a versioned internal lineage anchor proves one unique logical continuation. Financial content, timestamps, sequence indices, and fuzzy similarity never prove identity; deletion or any ambiguous split, merge, duplicate, or reorder retires the old identities and mints new ones. Joined display groups own separate IDs tied to their persisted exact link topology rather than inheriting an arbitrary child identity. History writers atomically commit their mutation, identity reconciliation, generation, and publication-dirty record; re-decode stages output before a per-logical-group atomic replacement, and bulk work publishes only after its durable barrier settles. Snapshot construction never creates or guesses identities: mapping inconsistency keeps the previous publication authoritative and schedules recovery. This accepts conservative identity churn where provenance is genuinely ambiguous in order to prevent a stale ID from silently naming a different financial event.
