# Refresh only while the client is in use

On launch or foreground resume, the Client will automatically Fetch the current Engine state and update its Portfolio Snapshot when reachable. Expensive external-source Refresh operations require an explicit user action, while Engine requests and WebSocket task or progress observation exist only in the active foreground. An authenticated mobile WebSocket has no dynamic subscription protocol and automatically receives only Snapshot Revision and authorized Refresh Operation notifications; REST Snapshot and active-operation reads reconcile every connection, so events are never durable state. The Client uses standard close codes, treats `1008` only as a trigger for fresh proof rather than a domain state, and bounds all reconnection to the foreground. It closes with `1000` as soon as it loses the active foreground, destroys its Access Session bearer on background or system lock, and obtains a new Access Session after returning; scheduled background work and push delivery are outside the first version.
