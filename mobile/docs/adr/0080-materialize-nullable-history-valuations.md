# Materialize nullable History valuations

Every Companion History Event will carry `value` as either a canonical exact-decimal string or null in the Published Snapshot's single `valuation_currency`. The value is the Event amount valued for that Event's own timestamp, never the Group occurrence time, a current-price fallback, implicit USD, or a Client-side conversion. The Engine materializes this field in an encrypted Profile-owned History valuation projection using only deterministic locally available historical-price inputs; Snapshot Fetch, older-page reads, bootstrap, and serialization never query a remote oracle. Missing valuation is null and a genuine zero is `"0"`. Events expose neither unit price, oracle metadata, nor a synthetic Group total, because summing swap legs would not define one meaningful activity value. A controlled revaluation, main-currency change, or relevant Event mutation atomically updates the projection, advances History Generation when public content changes, and republishes coherently, while unrelated mutable cache state cannot alter an active generation. This adds storage and projection work but preserves useful exact offline fiat context without making Companion reads network-dependent.
