# Derive History Group locations from Events

Every History Event will carry one required canonical Engine `location`, while a History Group will carry a required non-empty `locations` array equal to the canonically sorted and deduplicated union of all its included Events. There is no singular group anchor location. The array is descriptive rather than directional: movement and bridge UI obtains out/in locations by dereferencing Summary role IDs, and a generic multi-location card may show the primary Event's location plus a count. Location is independent of History Source Attribution and typed transfer-rail `blockchain`; neither can substitute for it or invent a missing counterpart. The location filter is Event-scoped and must match the same Event as active asset/type/subtype/Source predicates before the complete Group is returned. This represents exchange-to-chain, exchange-to-exchange, and cross-chain joins without making primary selection or an accidental SQL aggregate row define the location of the entire activity.
